# 单元测试设计说明书

**项目名称：** sup-iam 身份识别与访问管理系统

---

# 1. 引言

## 1.1 编写目的

帮助开发人员快速理解 sup-iam 项目的单元测试设计思路和实现思路。本文档描述项目的测试策略、Mock 模式、分层约定和工具链选择，不逐一罗列用例。

## 1.2 适用范围

`internal/` 下所有模块的单元测试。

---

# 2. 测试策略

## 2.1 分层约定

| 层次 | 典型路径 | 测试原则 | Mock 策略 |
|------|---------|---------|----------|
| **case / service** | `internal/*/v*/service/` | 覆盖核心业务逻辑，mock 下层 repo/cache | 接口 mock |
| **api (handler)** | `internal/*/v*/go/` 或 `*/*/api/` | 覆盖参数校验和错误响应，mock service 层 | 接口 mock |
| **repository / store** | `internal/*/v*/repository/mysql/` | 覆盖 SQL 组装，用 sqlmock 避免真实数据库 | sqlmock |
| **cache** | `internal/*/v*/cache/` | 覆盖读写逻辑，可测试真实缓存实例 | 轻量配置 |
| **rpc** | `internal/*/v*/rpc/` | 覆盖消息转换，mock 上下游 | 接口 mock |

## 2.2 隔离原则

- **数据库隔离**：使用 `sqlmock` 模拟 MySQL 驱动，不依赖真实数据库
- **网络隔离**：外部服务（Redis、gRPC、Etcd）均通过接口隔离，测试中替换为 mock
- **时间隔离**：依赖时间的逻辑（过期、超时）使用 `time.Now()` 配合测试数据的时间偏移验证

---

# 3. Mock 模式

## 3.1 接口驱动

所有外部依赖抽象为接口，测试层注入 mock 实现：

```
被测模块 → 接口依赖 → 生产: 真实实现
                     测试: mock 实现（gomock / 手写）
```

## 3.2 工具选择

| 工具 | 用途 | 说明 |
|------|------|------|
| `go.uber.org/mock` (原 GoMock) | 自动生成接口 mock | 配合 `//go:generate mockgen` 指令自动维护 |
| 手写 mock | 轻量依赖（如 io.Writer） | 避免引入 mock 生成工具链的过度设计 |
| `sqlmock` | MySQL 驱动模拟 | repository/mysql 层的 SQL 验证 |

## 3.3 生成方式

```bash
go generate ./internal/...
```

在每个包含 `//go:generate mockgen ...` 注释的源文件上执行，自动更新 `mock/` 目录下的 mock 实现。

---

# 4. 测试数据管理

## 4.1 测试套件模式

对于独立模块，每个测试文件维护自身所需的数据。对于需要全局共享初始化的模块，使用 `TestMain` 一次性初始化和拆除：

```
被测包/
├── xxx_test.go        # 单元测试
├── xxx_bench_test.go  # 基准测试（可选）
├── mock/              # gomock 生成的 mock
│   └── xxx_mock.go
```

## 4.2 数据准备

- case/service 层：测试函数内部直接构造入参和 mock 期望
- repository 层：通过 `sqlmock.NewRows` / `NewResult` 模拟 SQL 返回
- 避免在测试间共享可变全局状态；必须共享时（如缓存），在 TestMain 中初始化，各 Test 通过辅助函数切换数据集

---

# 5. 测试运行

## 5.1 执行

```bash
# 单包
cd internal/xxx
go test -v -count=1 .

# 全项目（跳过集成测试）
go test -count=1 -short ./internal/...

# 覆盖率
go test -coverprofile=coverage.out -coverpkg=./internal/... ./internal/...
go tool cover -html=coverage.out
```

## 5.2 约定

- 测试文件与被测文件同包，可访问私有符号
- 测试函数命名：`TestXxx_Yyy`（功能_场景）
- 基准测试命名：`BenchmarkXxx_Yyy`
- `TestMain` 仅在需要全局初始化的包中使用，其余场景不需要
- 测试循环标记 `-count=1` 避免结果缓存干扰
